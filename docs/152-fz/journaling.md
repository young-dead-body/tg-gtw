# Журнал учёта операций с персональными данными

**Версия документа:** 1.0

Настоящий документ описывает систему журналирования операций, связанных с обработкой
персональных данных (ПДн), предусмотренную 152-ФЗ и реализованную в Сервисе. Цель — дать
полную, достоверную и защищённую от искажения запись: **«кто, когда, с какого устройства и
какого IP, над какими данными и какое действие совершил»**.

## 1. Источник данных

Журнал формируется из таблицы `audit_log` (миграция `000004_create_audit_log`) и архива
`audit_log_archive` (миграция `000012_create_audit_log_archive`). Записи создаются единой
функцией `recordAudit` во всех критичных обработчиках (`api/internal/app/audit.go`).

Поля записи: `id`, `user_id` (субъект/актор), `action`, `entity_type`, `entity_id`,
`ip`, `user_agent`, `details` (JSON), `created_at`.

## 2. Перечень фиксируемых событий

| Событие                  | Действие               | Что фиксируется                                       |
|--------------------------|------------------------|--------------------------------------------------------|
| Вход успешный            | `login.success`        | пользователь, IP, UA                                   |
| Вход неуспешный          | `login.failed`         | e-mail, IP, UA, причина                                |
| Выход                    | `logout`               | пользователь, IP                                       |
| Смена пароля             | `password.changed`     | пользователь, IP, факт смены                           |
| Создание пользователя    | `user.created`         | администратор, созданный пользователь                 |
| Изменение пользователя   | `user.updated`         | администратор, изменённые поля (`details`)             |
| Удаление пользователя    | `user.deleted`         | администратор, удалённый идентификатор                 |
| Принятие согласия        | `consent.accepted`     | версия документа, IP, UA                               |
| Управление согласием/доступом | `consent.*`, доступ-события | администратор, объект                                 |

## 3. Неизменность и защита

- Записи журнала недоступны на изменение пользователями: их создают только внутренние
  обработчики; API отдаёт журнал лишь администраторам с аутентификацией и авторизацией.
- Признаки подлинности: полный набор метаданных (actor, action, entity, ip, ua, timestamp);
  записи не перезаписываются (INSERT-only).
- Целостность архива на уровне БД (схема `audit_log_archive`), доступ к нему ограничен.

## 4. Сроки хранения и архивирование

- Активный журнал ведётся в `audit_log`.
- По истечении срока (настройки S16: `ARCHIVE_*` — порог по возрасту записей) строки
  переносятся джобой `internal/cron/archive.go` в `audit_log_archive`.
- По истечении срока хранения архива строки удаляются джобой (`DeleteArchivedLogs`).
- Резервное копирование — `pg_dump` (джоба `internal/cron/backup.go`) в `/backups`.

## 5. Порядок предоставления данных журнала

Администратор Сервиса вправе выгружать журнал через интерфейс (эндпоинты журнала аудита и
статистики) с ограничениями по авторизации. Доступ к архиву и резервным копиям — только
ответственный за организацию обработки ПДн.

## 6. Контроль

Корректность журналирования проверяется тестами (`api/internal/app/audit_test.go`,
`api/internal/cron`). Внесение изменений в схему журнала оформляется новой миграцией и ревью.
